# 项目状态与验证边界

更新：2026-10-14。本页记录可公开核对的实现与限制；历史实验细节见 `docs/lessons/`，逐文件改动归属见 `workbench/PROVENANCE.md`。

| 能力 | 当前实现 | 边界 |
| --- | --- | --- |
| 学习任务工作流 | 复用上游 Coordinator、Reviewer、Retriever、Gate 和 Worker 编排；本项目增加 guided/deep 两条学习路径、明确高风险请求的只升级路由下限，以及显式双主体比较题的三步确定性证据计划；Top-K 排满而缺主体时最多补查一次 | 普通题 Planner 仍是固定步骤列表；比较计划仅支持两个定向检索、一次受限本地补查与证据汇合，不是模型自由拆解、通用 DAG 或 checkpoint 续跑；风险保底是窄范围词面规则 |
| 检索与证据 | 七份有来源的本地课程资料；复用上游 BM25、轻量词项相似度、词项共现与 Evidence Ledger；本项目在真实 `retrieve → reason` 边核对片段、源文件、哈希及证据记录 | 所谓“语义”并非 Embedding，“Graph”并非实体多跳；交付契约只覆盖这一条边 |
| 止答与发布 | 无合格证据时学习场景跳过 Worker；新增 Gate 后发布策略、严格题独立最终 Reviewer、引用 ID/哈希/摘录的结构核验 | 上游 `verify` 节点不核验 Worker 答案；结构核验不能证明语义正确；Gate 未放行时上游流程仍可能已调用 Worker |
| 会话与预算 | 复用上游按 thread 的近期会话存储；本地 SQLite 在真实千问请求前预占名额，上限 100 次；HTTP 403 等不可重试错误已在首次失败后停止。坏计划、交付失败、模型不可用、比较计划源变化或检索超时会写本地脱敏失败终态 | 未做长期学习者画像、并发版本控制、写工具幂等或 Skill 自动修订；本地补查不是通用续跑；调用计数、会话与失败文件只留本机 |

## 已有实验

- 2026-10-14 发布前运行完整工作副本的 **142 项离线测试**：第一次只有旧 Web 状态测试在固定的一秒轮询窗口内超时；该单测单独重跑通过，第二次完整回归 **142/142 通过**。仍不能断言没有偶发延迟。测试修改的本地示例 Ledger 已恢复到固定上游内容。
- 同日运行三题离线演示：概念题 `guided/answered`（3 次脚本模型调用），条件题 `deep/answered`（4 次），语料外题 `guided/abstained_no_evidence`（2 次、无 Worker）；真实千问请求 **0 次**。演示只核对流程，不证明真实模型答案质量。
- 12 题检索集记录了片段存在、召回、过滤、Top-K 与 Gate 资格。原六文档基线：开发集标注原文资格 **5/5**、留出集 **0/3**。加入有出处的二叉树定义后，该题可取得合格片段，但出现“满/完全二叉树区别”误放行；本项目随后增加窄范围双主体覆盖检查，在已测反例中于 Worker 前止答。
- 另设跨语言开发 3 题、留出 2 题。原始英文锚点合格均为 **0/3、0/2**；只在评测器试验的双语别名为 **1/3、0/2**，因此没有接入应用。无证据表象可能来自资料缺失、候选排序或资格阈值，不能统称资料缺失。
- 一次真实“哈希冲突”请求的阶段事件显示：路由约 **8.107 秒**、路线复核约 **19.441 秒**、Worker 约 **14.316 秒**，本地检索约 **0.033 秒**。阶段合计约 **41.90 秒**，不是精确端到端耗时；这些数据只说明那一次的串行模型调用是主要耗时，尚未实现提速。
- 2026-09-29 最后一次只读核对的真实千问累计为 **12/100**。这不是新发布后的调用量，也不能推断公开仓库使用者的调用量。
- 2026-10-14 新增一键离线验收，七类代表性终态 **7/7 通过**；六个正常响应案例都走同一条 10 节点主链，从轨迹观察到 Spec 的 **9/14 条声明边**，不是系统路径覆盖率。学习场景单元测试 **16/16 通过**；本轮完整 142 项回归有一项已知 Web 状态轮询超时，单测复跑通过。详情见[最小闭环测试报告](MVP_TEST_REPORT.md)。
- 同日真实千问烟测在第一步路由返回额度类 HTTP 403，未得到真实回答；本地预占数因统一重试从 **12/100** 增至 **14/100**。失败后没有再次发起请求或更改账号设置。此前成功的真实“哈希冲突”案例属于历史观察，不能替代本轮真实端到端通过。
- 随后按这个失败案例修订模型错误分类与重试：模拟 403 在路由和 Worker 均只尝试一次，模拟 503 保留至多一次重试；单次命令行失败不再打印 traceback。完整工作副本 **147/147 项通过**，七类离线验收再次 **7/7 通过**，真实请求 **0 次**，本机计数仍为 **14/100**。旧 Web 状态测试改用最多五秒的有界等待，完整回归与该单测重复 **10/10** 通过；未证明运行时没有竞态。详细断言见[最小闭环测试报告](MVP_TEST_REPORT.md)第 5 节。
- 2026-10-14 后续核对发现：学习场景强制检索，因此 `plan_to_reason` 在此场景不可达；重试上限为 0，`verify_to_reason` 也尚无运行时选择逻辑。新增显式双主体比较题的三步证据计划后，测试记录 Retriever 确实依次查询两个主体。两侧资料齐全的测试案例完成计划；正式语料缺少一侧定义时，汇合任务失败并跳过 Worker。缺依赖、循环、不可用处理器和超步数在检索前拒绝。学习场景 **21/21**、完整副本 **148/148**、离线终态 **7/7** 通过；真实千问 **0** 次。详见[第十六课](lessons/LEARNING_16_REACHABILITY_AND_BOUNDED_PLAN.md)。
- 2026-10-14 再增加异常路径的脱敏持久终态。四种坏计划、四种坏交付和模拟模型 403 均记录具体状态；正常响应不产生失败文件，Worker 未调用或会话未保存的原有边界保持。输入、thread ID、模型错误正文与服务商代码不落盘；写失败也不遮盖原异常。学习场景 **23/23**、完整工作副本 **150/150**、七类离线验收 **7/7**；本轮真实千问 **0** 次，本机预占 **14/100**。详见[第十七课](lessons/LEARNING_17_FAILURE_TERMINALS.md)。
- 2026-10-14 的第十八课在比较计划中加入最多一次受限 Top-K 补查（4→12，`min_score=0.08` 不变）。同初态脚本模型开关对照：两侧定义可见时 `answered→answered`、本地检索 2→2；定义被 Top-K 挤出时 `abstained_incomplete_evidence→answered`、检索 2→3、模型调用 2→3；语料真缺定义时仍 `abstained_incomplete_evidence→abstained_incomplete_evidence`、检索 2→3、模型调用 2→2。源文件在检索中、Worker 前或 Worker 生成期间改变，以及补查超时，均无该轮会话快照。完整副本 **157/157**、学习场景 **30/30**、八例离线验收 **8/8**；观察到的工作流相邻边仍 **9/14**，完整节点序列仍 **1** 种。本轮真实千问 **0**，本机预占 **14/100**。详见[第十八课](lessons/LEARNING_18_BOUNDED_RETRIEVAL_RECOVERY.md)。
