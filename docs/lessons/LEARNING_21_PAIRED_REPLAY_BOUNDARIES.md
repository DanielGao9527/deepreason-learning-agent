# 第二十一课：固定初态回放能证明什么

**历史基线说明：**本课表中的严格题原为发布；第二十三课加入严格题覆盖契约后，该题在相同空泛脚本答案下扣稿。当前配对回放仍为 7/7，详见[第二十三课](LEARNING_23_STRICT_ANSWER_COVERAGE_CONTRACT.md)。

开发路径 E 的第一步不是宣称答案变好了，而是给第二十课的新 Skill 做**同条件回归**：它批准前后只能影响适用的 Worker 教学提示，不能意外改变路由、Gate、止答、发布或模型调用次数。

`scripts/replay_learning_skill_paths.py` 对每个案例分别创建新的临时工作区，复制同一批课程资料，建立同一条明确反馈笔记，使用同一个确定性脚本模型；两次运行唯一的策略差异是比较题 Skill 是否经哈希核对批准。脚本核对两侧课程文件的 SHA-256 指纹相同、开始时均无问答会话，并在每次运行后检查最终答复确实进入本轮会话；坏交付则必须只有脱敏失败记录、没有会话快照。机器报告保留每轮 run ID、阶段轨迹、模型角色调用、Gate、发布状态、耗时和 Skill 版本，位于本机 `artifacts/analysis/learning_skill_paired_replay.json`。

| 案例 | 两侧期望且实测终态 | 每侧脚本模型调用 | 批准后教学 Skill 是否进入 Worker |
| --- | --- | ---: | --- |
| 哈希冲突概念题 | answered | 3 | 否 |
| **留出形式的哈希表/二叉搜索树比较题** | answered | 3 | **是** |
| 缺一侧定义的树形比较题 | abstained_incomplete_evidence | 2 | 否，Worker 未运行 |
| 语料外协议题 | abstained_no_evidence | 2 | 否，Worker 未运行 |
| 删除生产数据请求 | blocked / Gate deny | 2 | 否，Worker 未运行 |
| “一定更快吗”严格题 | answered / 独立复核后发布 | 4 | 否 |
| 证据 ID 损坏 | handoff_rejected；无会话 | 2 | 否，Worker 未运行 |

七组配对的预期终态 **7/7**，两侧控制流差异 **0/7**，批准后的目标 Skill 加载 **1/7**；脚本模型调用总差 **0**，真实千问请求 **0**。坏交付的失败原因是 `evidence_missing`，尚未到 Gate 与发布。批准前后 Worker 的提示改变已经在第二十课的完整问答测试中确认，本课进一步证明这条新策略没有让已测的非目标案例改道。

**解释边界：**脚本 Worker 的答案文本固定，不会因为教学 Skill 改变而生成更好的解释。因此“调用差 0”和“终态相同”只描述这个离线脚本实验；没有测 token 数，实际千问请求时间与答案质量均未知。七题中有若干沿用最小闭环的代表题，因此也不能叫完全独立的大规模留出集；新增的成功比较题只检验 Skill 在另一组概念上是否触发，不评估内容正确性。阶段耗时保存在报告中供诊断，没有把临时目录内的小样本耗时差写成性能提升。

本次没有新增工作流可达边；原八例离线验收仍观察到声明 14 条中的 9 条相邻边与一种完整成功节点序列。后续要做**答案级**研究，需另建人工标注的比较题与反例，固定模型版本、采样参数、语料和初始状态，再统计“前提是否覆盖、是否误引用、是否无证据仍发布”的分子/分母及每题调用/token/时间。额度不可用时只能保留本课的控制流结论，不能把 7/7 写成答案正确率。

复用部分：上游多角色编排、工作流、Gate、SessionStore 和阶段事件；此前本项目的学习路径、失败终态与 Skill 审批。新增加的配对回放、固定初态校验、失败与会话终态核对、成本计数和报告，是本项目与 AI 协作实现。

从仓库根目录 PowerShell 复现：

```powershell
.\.venv\Scripts\python.exe scripts\replay_learning_skill_paths.py
```
