# 第十三课：为什么“有检索结果”仍可能答错

更新：2026-09-29。本课覆盖 V1 第一步基线与第二步的一次资料补充、一次窄范围发布前检查。它不是模型回答正确率实验；本课没有发送千问请求。

## 先把三件事分开

1. **语料是否有依据**：六份原资料有没有足以回答问题的段落。
2. **检索是否送到依据**：人工标注的关键段落是否进入 Top-K 并获得证据资格。
3. **系统是否允许生成**：Gate 有合格证据、学习场景的附加检查通过后，Worker 才会被调用。Worker 被调用不等于答案正确。

上游 `knowledge.py` 把 BM25、轻量词项余弦相似度与词项共现分数组合；这里的 `semantic` **不是向量 Embedding**，`graph` **不是实体知识图谱**。`workflow.py` 的技术题资格规则先看是否存在一个综合分和 semantic 子分都达标的本地块；一旦存在，就可能把本轮其他选中证据一起标成合格。这解释了为什么“合格证据数=3/4”不能当成“关键依据已找到”。学习场景当前综合分门槛 0.45、semantic 子分门槛 0.10、Top-K=4。

## 固定材料与人工标签

六份原资料冻结在 `workbench/deepreason/evals/corpus_v1/`；12 个手工题和原始标签在 `workbench/deepreason/evals/learning_questions_v1.json`，开发集 8 题、留出集 4 题。有依据的题逐条给出文件名和原文锚点；无依据题说明缺哪项定义/步骤。评测脚本 `scripts/eval_learning_baseline.py` 固定 required+soft 路由，逐题复制材料到隔离临时目录，记录各路分数、过滤前后、Top-K、Gate 资格和输入哈希。它不测路由模型、Worker 质量、真实延迟或 token。

六份资料的基线报告：`artifacts/analysis/learning_v1_baseline_2026-09-29.json`。重复运行生成的报告 SHA-256 完全相同。开发集 5/5 道有依据题把标注片段送进 Top-K 并获得资格；3 道资料外题没有合格证据。留出集 3 道有依据题的**人工标注英文原文片段为 0/3**：两道检索评分为零，一道在 0.08 最低分处被过滤；然而这三题均有其他中文近邻片段获得 Gate 资格。它们不能计作正确回答。留出集另有 1 道资料外题无合格证据。

用户真实问过的“二叉树是什么”在六份资料中缺一般定义；最高候选是二叉**搜索**树，综合分 0.644、BM25 子分 1.0、semantic 子分 0.087885，低于 0.10。现象同时包含**资料缺失**与**候选资格不足**，不是只把阈值调低就能修好。

## 一次单因素补资料，以及它暴露出的风险

依据 [OpenDSA 的二叉树定义](https://opendsa.cs.vt.edu/ODSA/Books/Everything/html/BinaryTree.html)撰写一份简短中文提要 `07_binary_tree_definition.md`；[OpenDSA 许可](https://opendsa.cs.vt.edu/home/license)为 MIT。本项目文件的哈希与来源记录在 `learning_mvp/CURATED_SOURCE_MANIFEST.json`。它不是原先固定 OpenDSA 提交中的 RST 原文；来源网页是当前页面，本地提要由文件哈希固定。

只加这份资料，不改检索权重和阈值；原 12 题中只把“二叉树是什么”从资料缺失改为有依据，覆盖标签文件为 `evals/learning_questions_v1_binary_source_override.json`。资料版对照报告 `artifacts/analysis/learning_v1_binary_source_2026-09-29.json` 显示该题新段落综合分 0.662、semantic 子分 0.134583，进入 Top-K 和 Gate 资格。

但“满二叉树和完全二叉树的定义有什么区别”仍缺两个特殊树形的定义；新增的一般定义却得到综合分 0.682、semantic 子分 0.186272，Gate 给出 4 条合格证据。这是 **1/2 道开发集无依据题发生资格暴露**，说明词面相关性会误导门禁。这个实验不能写成“检索准确率提升”。

## 小范围补救与故障边界

在 `learning.py` 的 Worker 调用前，新增只识别少数显式 **“A和/与B有什么区别/有何不同/怎么区分”** 问法的主体覆盖检查：如果合格片段合起来没有同时出现 A、B 两个完整名称，就跳过 Worker，返回资料不足，学习结果标为 `abstained_incomplete_evidence`。这道检查不修改上游 Gate 的 `allow` 或原始合格证据数，避免把应用级扣稿冒称为 Gate 通过率改进。三种故障问法的脚本模型回归均未调用 Worker；其中“请解释……有何不同”是上游原有 Gate 因无合格证据先行止答，不能算新检查的贡献。

加入检查后的报告 `artifacts/analysis/learning_v1_binary_guard_2026-09-29.json`：开发集 6/6 道有依据题的标注片段获得资格；2/2 道无依据题均不具备确定性 Worker 放行条件，其中“满/完全”由新检查挡下。完整工作副本的脚本模型测试覆盖“二叉树可继续”“满/完全缺定义则跳过”“测试材料补齐两种定义后可继续”，全套 **138 项离线测试通过**。这些是路径与扣稿验证，不是千问答案质量验证。

限制必须记住：检查只认少数显式中文比较句式，不能自动判定所有复合题的条件是否齐备；两个名称都出现也不能证明定义、关系或结论正确。留出集 3/3 道有依据题仍缺人工标注的英文原文片段，却仍具备 Worker 调用条件。这是下一步需要处理的跨语言/证据资格问题，不能从本课宣称全局 RAG 改善。真实千问请求计数保持 12/100。
