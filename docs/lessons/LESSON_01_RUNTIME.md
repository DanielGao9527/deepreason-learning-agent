# 第一课：模型说“调用工具”，程序实际做了什么

目标：讲清一次工具循环，能预测工具预算改变后的行为。当前是脚本模拟模型，工具与保存动作真实执行。

## 先看一个任务

输入：“比较两个演示方案的任务执行方式，并给出依据。”

两份材料是项目里特意编写的合成示例，便于观察控制流程。整个过程是：

```text
用户任务
  ↓
模型请求 list_sources
  ↓ Runtime 查找并执行 Python 工具函数
工具返回资料目录
  ↓ 把工具结果加入消息，再调用模型
模型请求 read_source(A)、read_source(B)
  ↓ Runtime 依次执行两个读取
工具返回两份正文
  ↓ 把正文加入消息，再调用模型
模型返回报告，不再请求工具
  ↓
Runtime 结束，保存消息和事件；演示入口保存报告
```

两次读取在当前核心中**按顺序执行**。一次模型响应可以带两个工具请求，这不代表并发执行或两个 Agent。

## 五个关键位置

| 名称与位置 | 白话含义 |
| --- | --- |
| `ToolCall`，`runtime.py` | 一张请求单：本次调用 ID、工具名字、参数。它本身不会执行代码 |
| `ToolCallingModel.complete()`，`runtime.py` | 模型接口：收历史消息和工具说明，返回文字及可选工具请求。`Protocol` 描述所需方法，不实现模型 |
| `RuntimeTool.action`，`runtime.py` | 真正执行动作的 Python 函数。模型只能请求已注册的名字，Runtime 找到函数后执行 |
| `AgentRuntime.run()`，`runtime.py` | 循环控制：问模型 → 检查预算/工具/参数 → 执行 → 回填结果 → 再问模型 |
| `ScriptedResearchModel`，`deepreason_lab/demo.py` | 为教学写的固定决策：没目录就请求目录，有目录就请求正文，有正文就组成报告 |

`dataclass` 可以理解为简洁的数据记录写法；这里不用先学复杂设计模式。先理解每条消息里存了什么，下一步由谁决定。

## 结果怎样真正回到模型

第二次模型调用前，消息中已经有 `list_sources` 的实际返回内容。模拟模型从这段返回内容读出 ID，再产生读取请求。最后一轮从 `read_source` 的真实返回内容拼成报告，工具正文并非只写进日志后被忽略。

回填消息包含 `role="tool"`、`tool_call_id`、工具名和结果正文。调用 ID 把“请求单”和“返回单”对应起来，工具名不能替代调用 ID：一次可以请求同一个工具两次。

真实千问接入后，需要把这些内部结构转换为供应商要求的消息和工具格式，再把响应转回 `ToolModelResponse`。目前尚未实现该转换；内部格式不能假定能原样发给任何模型。

## 动手实验

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe run_demo.py
```

正常轨迹有 **3 次模型调用、3 次工具调用、7 条消息**：用户任务、第一次模型请求、目录结果、第二次模型请求、正文 A、正文 B、最终回答。第二次请求包含两项工具调用，所以模型轮数和工具步数不是同一个概念。

然后限制只能调用两次工具：

```powershell
.\.venv\Scripts\python.exe run_demo.py --max-tool-steps 2
```

先预测，再看输出：目录一次 + 读取 A 一次，用完预算；读取 B 前停止。状态应为 `step_limit`，退出码为 2。程序保留轨迹，不生成完整报告。`tool_steps` 在当前实现里统计已返回结果的步骤，失败尝试并不全部计入，不能直接当总尝试次数。

最后尝试预算为 3，判断它是否足够。完成三次工具调用后还可以再问模型给出最终回答，因为该限制约束工具执行，不等于禁止下一轮模型调用；模型轮数另有 `max_turns`。

不需要先改几十个文件。能解释这两个预算和结果回传，就已经理解运行核心的一块重要机制。

## 这段代码已经有的东西与边界

- `completed`：模型没有再请求工具；不自动证明报告正确。未来需独立检查任务要求和产物。
- 参数检查：已有必填字段和基础类型校验；不是完整 JSON Schema 验证。
- 快照：上游在返回结果时保存状态。新一次 `run()` 仍从新用户消息开始，当前没有跨进程恢复，也不是每步都持久化。
- 超时：线程等待可以超时，但已运行的线程可能继续；不能把它当成副作用已取消。
- 幂等缓存：当前 Runtime 实例内复用相同工具/键的结果；不是持久化事务，也没有完整参数冲突保护。
- 门禁：仅对声明了 `approval_action` 的工具调用；当前只读演示未使用它，不能称作通用沙箱。
- 失败：多种错误会结束任务；尚未把错误结果发回模型做自动修正。

这些边界用于理解和选范围，不意味着必须逐项修复上游。下一课优先把模型接口和工具格式讲透，接千问，然后再讨论哪个恢复机制最值得做。
