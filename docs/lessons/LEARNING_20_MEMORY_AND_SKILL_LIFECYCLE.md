# 第二十课：记忆边界与一个受控教学 Skill

这是开发路径 D 的小实验。先按源码核对“记忆”到底在哪儿读写，再从一条明确保存的反馈笔记形成**比较题先说明前提**的教学 Skill 候选。它解决的是候选何时可以生效、何时必须止住，不声称模型已自动从失败中学习，也不把三道触发测试写成教学正确率。

## 上游与本项目的实际读写

| 信息类型 | 真实位置与读写 | 在学习助手中的边界 |
| --- | --- | --- |
| 当前任务状态 | 上游 `AgentState` 保存本轮路线、计划、证据、Gate 与节点轨迹 | 运行期间的状态；本身不是跨会话画像 |
| 近期对话 | 上游 `ShortTermConversationMemory` 保留滚动窗口，`SessionStore` 按 thread 保存最终交付后的问答并可在重建对象后恢复 | 学习场景最多保留 6 轮；只有发布后的答复进入近期会话，不等于失败点 checkpoint 续跑 |
| 历史证据与失败痕迹 | `Evidence Ledger` 记证据；本项目 `local_state/failures/` 记录脱敏异常终态 | 可审计，但没有自动检索历史失败再规划的运行机制；检索阶段的 Ledger 写入不能由失败自动回滚 |
| 本地学习笔记 | 第十九课 SQLite `learning_notes.sqlite3`，仅明确 `--save-note` 写入，读写按 thread 命名空间与版本受控 | 默认**不注入**问答提示，也不是用户能力画像；thread ID 没有登录认证 |
| 上游长期记忆 | `memory.py` 按 `semantic/episodic/procedural/project/user` 写 JSONL，要求 Gate 与证据；编排器把各分区尾部记录交给模型 | 学习场景重写 `_write_explicit_long_term_memory` 为无操作，普通提问和“请记住”都不会自动写；上游分区文件本身没有账号隔离和相关性排序，不能直接当多用户画像 |
| 公共知识 | `knowledge/` 文档走上游本地检索与证据资格 | 不是用户事实；修改源文件时比较计划会阻断迟到旧答 |
| Skill | 上游 `SkillRegistry` 只扫描 `SKILL.md` 前置元数据；`SelfEvolutionEngine` 只写 `proposed` JSON | 上游默认问答路径未把所有 Skill 内容动态注入 Worker，也没有“反馈→评测→审批→生效→回退”的通用闭环 |

如果借用 Hermes 的“热/温/冷/外部”来理解：当前状态和近期会话最接近热记忆；明确笔记与历史执行证据是较持久的个人/运行材料，但当前**并不自动召回**，不能硬称已建好温层；公共课程语料是有来源的冷知识；外部网络在学习 MVP 关闭。Skill 是可复用的过程规则，不应混作用户事实。这个对应关系是设计类比，不是源码里已有的四级管理器。

## 这次增加的最小 Skill 闭环

场景：学习者明确保存反馈笔记“比较题缺少成立前提，希望先说明条件再说差异”。`LearningSkillStore.propose_from_note` 必须找到同一 thread、同一操作 ID 的已提交笔记，并用窄范围词面检查“比较”与“前提/条件/适用”。反馈原文只作来源，不直接成为系统提示；候选教学指令来自代码中允许的固定模板。候选记录来源笔记 ID、正文哈希、当前生效版本哈希与新内容哈希，写入本地忽略版本控制的 SQLite。

固定三例是：

1. **正常例**：“满二叉树和完全二叉树有什么区别？”且两侧证据齐全，应加载候选。
2. **前提变化**：同一题但证据不齐，不加载；实际问答中缺证据时 Worker 本来会被前置止答。
3. **反例**：“二叉树是什么？”不应触发比较题规则。

候选阶段给出旧版/新版的逐例触发结果。固定离线结果为：未启用版 **2/3**、限定比较题候选 **3/3**、过宽的 `any` 候选 **2/3**；过宽候选不能批准。**这三个数是规则触发正确性，不是模型答案准确率、用户学习效果或统计显著提升。** 新候选即使通过三例，仍保持 `proposed`，不改变运行中的 Worker。

显式 `--skill-approve` 必须提交候选 ID 与内容哈希。批准时重新计算内容哈希、重查来源笔记正文哈希、重算三例、核对候选创建时的旧版本哈希；再复用上游 `GatePolicy` 对 `update_skill` 检查明确审批、工作区目标路径和一条来源笔记证据。缺审批、编辑候选、评测数据被改、旧版已变化，均阻断。通过后保存新版本并激活。Worker 在 Gate 放行、两侧比较计划完成且有合格证据时，才把已审批教学指令加入 system prompt。`--skill-rollback` 必须核对当前哈希并过 `update_skill` 审批 Gate，切回旧版本；历史版本不删除。测试既检查提示拼装，也用完整学习问答的脚本模型跑“批准前→批准后→回退后”三次，观察 Worker 实际收到的提示。

## 本机演示与结果

一条命令运行固定初态实验，无 API Key、无真实千问：

```powershell
.\.venv\Scripts\python.exe scripts\eval_learning_skill_candidate.py
```

输出报告在本机 `artifacts/analysis/learning_skill_lifecycle.json`，记录三例旧/新触发数、过宽候选拒绝、明确批准版本 1、回退版本 0，以及真实千问请求 0。若要在自己的本地 thread 尝试，先用第十九课命令保存一条确实提到“比较”与“前提/条件/适用”的反馈笔记；再运行 `run_learning.py --skill-propose-from-note <操作ID> --thread <同一thread>`，查看候选哈希和三例结果。审批命令需填返回的候选 ID 和哈希：`run_learning.py --skill-approve <候选ID> --candidate-hash <内容哈希>`；`--skill-status` 查看生效版本；`--skill-rollback 0 --expected-current-hash <当前哈希>` 可退回关闭版。这些批准命令是本地显式操作，**没有账号认证**，不适合直接暴露到多人服务。

代码位置：上游 `memory.py`、`skills.py`、`evolution.py`、`multiagent.py` 是被核对的原有机制；`learning_skill.py`、`learning.py` 的受限 Worker 接线、`tests/test_learning_skill.py` 与离线对照脚本是本项目与 AI 协作新增。第十九课笔记事务是来源底座。完整验证数见项目状态。

尚未做：从大量真实反馈自动发现候选、自由生成安全的新 Skill 文本、按账号隔离、跨任务 Skill 通用匹配、语义正确性评测或真实千问回答前后对照。上游 `SelfEvolutionEngine` 的 `proposed` JSON 也没有被这套小实验改造成通用发布器。下一步应固定一组**独立于三例触发集**的真实教学题，比较批准前后答案中的前提覆盖、误触发和模型调用成本；若没有真实模型额度，先保留“触发闭环已验证、教学收益未验证”的结论。
