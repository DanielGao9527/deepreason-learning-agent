# 第五课：证据门禁到底检查了什么

更新：2026-09-25。阅读固定上游 `workflow.py`、`gates.py`，并在临时目录运行 `scripts/trace_gate_decisions.py`。五个案例的原始字段见 `artifacts/analysis/five_gate_paths.json`。这些是直接给工作流传入固定路线、使用合成论文记录和空检索替身的**离线实验**，没有调用 Coordinator、Reviewer、Worker、千问或互联网。

## 先分清三个问题

1. **路线要不要证据？** 这是上游路由结果中的 `evidence_mode`、`risk_level`、`category`、`sources` 等字段。本实验固定输入，不测模型能否正确分类。
2. **证据算不算数？** `workflow._qualified_gate_evidence` 按任务类别挑选：学术类只接受 paper/web/user_experience 等外部来源；部分技术类优先外部来源，缺少外部来源时还要本地检索质量达到门槛。本地默认总分至少 0.45；若检索方法含 semantic，还要求语义分项至少 0.25。这些数字是配置阈值，不是“真实性概率”。
3. **证据够不够？** `GatePolicy.evaluate` 默认中风险要 1 条，高/极高风险要 2 条。条数不足一般为 `interrupt`；已批准状态与工作区路径边界也能影响动作门禁。但本次工作流传 `target_path=None`，所以实验没有验证文件操作边界。

## 五条实际分支

| 固定输入 | 实际状态 | 说明 |
| --- | --- | --- |
| 中风险、软证据、检索无结果 | `allow`，`evidence_status=exhausted` | 已尝试检索后允许**受限回答**，要求明确证据不足；`allow` 不代表已有事实依据。 |
| 高风险、严格证据、检索无结果 | `interrupt`，合格证据 0/2 | 不足以放行确定结论；工作流先重试一次检索，仍无结果才到门禁。 |
| 高风险、学术类、注入两条合成 paper | `allow`，合格证据 2/2 | 只证实**两条合成记录符合来源类型与数量规则**，没有检验论文真伪、独立性或结论是否被支持。 |
| 保护动作、语句含 `Drop database` | `deny`，`protected_denied` | 命中内置保护词组后，不能靠增加证据数量放行。没有执行删除命令。 |
| 同类保护动作、语句为 `Delete a production database` | `interrupt`，证据 0/2 | 没命中内置词组 `delete database`，因高风险证据不足而中断；这是**识别覆盖缺口**，不能把该分支称为已保护性拒绝。 |

最后两行尤其重要：`_is_protected_action_request` 用小写后直接查固定子串。它能匹配 `delete database`，但 `delete a production database` 中间插词后不匹配。当前结果仍是中断；如果另外给它两条合格证据，这个特定保护动作分支未必会拒绝。后者是按源码推断，**未作为本实验结果**。

## 为什么“有门禁”还不等于“报告可信”

`_gate` 判断的是类别、来源、检索分数、证据数量及少数动作词组。它没有逐句核验 Worker 最后写出的结论和证据之间的关系。`_verify` 在 Gate 允许时主要记录“门禁已通过”，不是重新审查答案。完整编排器之后仍会调用 Worker，上一课已用脚本模型观察到 Gate 中断后 Worker 仍可生成文字。门禁状态因此必须在**最终发布边界**再次执行；提示词中的“证据不足请克制”不能代替代码检查。

还有一个容易误读的细节：两条 paper 在临时目录中是脚本自己写入 ledger 的合成证据，目的是验证资格筛选与数量分支，不是证明“来源可信”。如果要把这些机制写入简历，准确说法应是“复现并分析证据门禁的资格与数量规则，构造软/严格/保护动作五种离线分支，识别固定词组漏判与最终产物缺少独立审查的边界”。这仍是学习分析，不能声称自己已经增强了门禁。

## 下一步怎么改，先验证什么

优先围绕一个明确的技术比较任务增加**最终产物审查**：把 Gate 状态、合格证据 ID、Worker 草稿交给审查器；代码先保证非 `allow` 不能发布确定结论，再让审查器定位关键结论及引用，并核对引用 ID 属于本轮合格证据、摘录存在。必要时只给一次定向修订机会，失败或超时则弃权。语义支持仍需独立标注的案例评估，不把“摘录存在”当成“论证成立”。

对保护动作的词组漏判，可以增加改写案例集并比较规则前后漏判与误拦截；真正的执行授权必须在工具调用处再独立校验，不能只靠问句分类。本轮没有修改上游策略，因此没有准确率提升数字。

复现：在项目目录运行 `.\.venv\Scripts\python.exe scripts\trace_gate_decisions.py`。脚本只向本项目的 `artifacts/analysis` 写汇总；案例工作目录为临时目录，结束即移除。
