# 第二十二课：证据到手，不等于答案教对

**历史基线说明：**本课数字来自第二十三课发布契约加入前的版本。当前同一空泛严格题已被扣稿；现行结果与复现方法见[第二十三课](LEARNING_23_STRICT_ANSWER_COVERAGE_CONTRACT.md)。

第十六至二十一课主要核对了控制流：计划是否被消费、资料缺失是否止答、Gate 与发布是否守住边界、Skill 是否只在合适场景进入 Worker。本课改问一个更接近用户体验的问题：**有合格资料并发布答案后，答案是否覆盖了问题必须解释的知识点？**

## 实验设计

`workbench/deepreason/evals/learning_answer_probe_v1.json` 从当前七份课程资料列出 4 道可回答题和 2 道应止答题。每道可回答题标有一个必须从合格检索片段找到的原文锚点，以及答案应包含的少量概念要点。题目与要点由本项目在 AI 协助下整理，**尚未经过独立人工标注**。语料字节指纹固定为 `36b913d8c5186a6bb6205ad1a27feee9033f896501a6a98066449c45fc8c8cc0`；资料变更时评测直接停止，不能沿用旧标签。

`scripts/eval_learning_answers.py` 为每题创建新工作区、新会话，使用相同的上游多角色运行流程与固定脚本模型，不发千问请求。它把失败分为：终态不符、标注资料没有进入**合格**检索结果、答案没有覆盖字面要点。分层是为了避免把“答案写得空泛”错诊为“没有资料”。所有逐题回答、调用角色和判断保存在本机 `artifacts/analysis/learning_answer_probe.json`。

| 观察 | 本轮结果 | 能说明什么 |
| --- | ---: | --- |
| 预期终态吻合 | 6/6 | 已测流程能走到预定回答或止答终态。 |
| 4 道可答题的原文锚点进入合格证据 | 4/4 | 这些题的必要资料在本轮检索中可见。 |
| 已发布答案覆盖全部字面要点 | 0/4 | 固定脚本 Worker 的笼统答复遗漏要点；**不是千问正确率 0%**。 |
| 两道缺资料题在 Worker 前止答 | 2/2 | 已测止答边界没有误调用 Worker。 |

严格题“哈希表一定比平衡二叉搜索树快吗”取得了相关资料，脚本 Worker 只回答“结论取决于问题条件。请回顾资料后自己判断精确查找与范围查询的差别。”独立 Output Reviewer 回 `supported`，提交了真实证据 ID、正确内容哈希下的原文摘录，程序结构核验通过，最终 `released_model_reviewed`。然而答复没有解释哈希查找与树的范围查询取舍，也没有最坏情况或平衡前提。这说明当前 Reviewer 模型判断和引用结构校验可以同时通过一段**教学内容不足**的答案；不是引用伪造漏洞，也不等于程序验证了语义支持。概念题则走 `released_gate_only`，同样没有答案级完整性保证。

这个探针刻意只做**字面覆盖诊断**。测试中的反向句“两个不同的键绝不会映射到同一槽位，所以哈希冲突不存在”包含全部关键词，会被字面检查误判为通过。因此 `0/4` 是固定脚本答案的要点匹配结果，`4/4` 是来源锚点可见性，**两者都不能称答案准确率**。真实答案的支持关系、错引、教学充分性和词语改写，需要人独立审阅，或有明确误判率的更强评测；不能把词项代理直接接成通用发布门禁。

源码归属：多角色执行、Retriever、Gate、Output Reviewer 为上游及本项目此前适配；本课新增 `answer_eval.py` 的离线归因器、六题要点集、单命令回放与三个校准测试。没有修改正式学习助手的路由、Worker、审查或发布策略，也没有消耗千问额度。

PowerShell 复现：

```powershell
.\.venv\Scripts\python.exe scripts\eval_learning_answers.py
```

下一步先让独立审阅者确认题目要点和逐题答案判定，再在**同一已固定模型配置、语料和新会话**下分别运行 Skill 批准前后，统计前提覆盖、错误引用、正确止答与请求/token/耗时。账号额度仍不可用时，不能把脚本结果外推到千问；也不能预写简历中的质量提升百分比。
