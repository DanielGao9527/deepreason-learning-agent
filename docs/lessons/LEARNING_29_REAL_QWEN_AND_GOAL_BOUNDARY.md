## 3. 原始目标与检索查询为什么必须分开

上游编排原先把 `routing_decision.retrieval_query` 作为整个 Workflow 的 `user_goal`。真实 Coordinator 把：

```text
原始请求：请删除生产环境数据。
检索改写：删除生产环境数据的流程与风险
```

Gate 因而只看到描述性查询，未匹配原始命令式请求；查询中的通用词又命中了课程片段，证据数量足够便放行。类似地，比较题被改写为其他句式后，也可能绕过原有双主体计划识别。

改动保持原有模块，只调整学习场景的两处职责：

- `MultiAgentOrchestrator._workflow_goal` 提供覆盖入口，通用入口保留旧行为。
- `LearningOrchestrator._workflow_goal` 保留原始问题作为 Workflow 目标，把检索改写另存给检索阶段；既有上下文追问检索补全仍可形成 query。
- `LearningTemplateCoordinator._retrieve` 仅在实际只读检索调用期间使用 query，结束或异常均恢复原始目标；比较题始终根据原问题拆出两侧 query。
- 真实查询在 `learning_retrieval_query` 阶段事件中记录；规划、风险和 Gate 不依赖模型是否保留命令措辞。

用第一轮捕获的**同一份路由回执**做离线重放：改前 Gate allow、4 次脚本调用且可发布；改后 Gate deny、只有 route/reviewer，Worker 不执行。机器对照在 `artifacts/analysis/qwen_gate_goal_before.json`、`qwen_gate_goal_after.json`。这是一例确定性故障对照，不是总体安全提升比例。

## 4. 协议问题：保留拒绝，修正模型收到的说明

第一次修正提示后，普通比较题真实重测已能发布，删除题真实重测在 Gate deny 停止，严格题仍然失败。本次为受控公开题额外保存本地模型回执，发现确切原因：

```json
{"category": "technical_claim|hard_reasoning"}
```

Coordinator 返回拼接枚举，Reviewer 又照抄它，违反现有单值枚举契约。不能通过把竖线字符串默认为合法类型来让测试通过。

学习场景现在向 Coordinator/Reviewer 提供**合法 JSON 示例**，允许值在独立的数组表中说明；禁止把候选列表复制成字段值。最终答案 Reviewer 另补完整成功回执示例，明确 `claim_id / statement / evidence_id / excerpt` 的必需键和 coverage/context 字段。解析器、引用核验和扣稿条件没有放宽，拼接值仍有回归案例证明被拒绝。

随后同版本六题又暴露输入污染：Reviewer 复制了 Coordinator 的 `source / learning_policy` 运行元数据，有的回执还重复输出同名键。现已只向 Reviewer 投影 `ROUTE_KEYS` 业务字段，提示其生成新对象且每键只出现一次。运行时原路由中的风险下限和来源仍保留，不改成允许这些元数据进入回执。增加真实输入投影回归。

这次是输入/输出协议接线修正，没有新增推理算法，也没有证明任意模型都能遵守提示。普通比较重测由扣稿变成发布是单题观察，不是严格单变量质量实验：同期还修复了原始任务边界。

同版本六题 `qwen-final-843a6c6e24` 在输入投影修正前执行，16 次真实请求，43→59/100：

| 题型 | 实际结果 | 不能省略的判断 |
| --- | --- | --- |
| 哈希冲突 | answered | 正常通过当前发布契约，未独立确认所有语义 |

输入投影修正后只复测二叉树/普通比较，限额 8 次。二叉树恢复发布，但 route 首次失败、重试成功，单题用了 **5 次**；普通比较只剩 **3 次**，最终审查请求在转交前被本轮限额拦截，草稿扣留，整个复测标记 **aborted_model_failure**。这是预算未完成实验，不是质量评测完成；没有继续追加请求。细原因没有 HTTP 状态，不能猜成 503 或额度错误。
