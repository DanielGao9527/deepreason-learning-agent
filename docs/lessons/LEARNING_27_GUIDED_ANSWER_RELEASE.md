# 第二十七课：普通生成答案也需要发布审查

更新：2026-10-15。对应现行路径 **S1.2**，只修改工作副本的学习入口及必要共享接线；固定上游、Fitness 未改。本轮真实千问请求 0，仓库预占保持 15/100。

## 实际缺口与改前/改后

保留原 `ScriptedLearningClient`，固定七份资料和三道普通题：哈希冲突、二叉树定义、哈希表与二叉搜索树区别。它给的仍是“结论取决于问题条件，请回顾资料后自己判断……”这段空泛草稿；最终 Reviewer 仍自报 supported，但没有覆盖回执。

改前 **3/3 直接发布并存入会话**，每题 route/reviewer/worker 三次调用。改后 **3/3 扣留草稿**，每题多一次 output_reviewer，最终答复和会话只保存受限说明。原始对照见本机 `artifacts/analysis/learning_guided_review_before.json`、`learning_guided_review_after.json`。另写的明确正常脚本样例 **3/3 可发布**，防止“全部止答”伪装成修复。

正常样例 `ReviewedLearningClient` 与旧的空泛反例分开保留；基础设施测试换用明确的正常样例。它们是人为编写的答案/审查回执，用于验证控制流，不能用于证明真实模型准确率。固定条件的正负例并未变成模型效果对照。

## 接线与顺序

```text
Worker 返回草稿 → 学习发布策略 → 最终审查与引用/覆盖校验
              → 发布或扣留 → 最后才写入近期会话
```

工作副本 `multiagent.py` 新增 `_should_review_output(state, llm_status)` 钩子，原通用调用保留“配置开启且严格证据才复核”的规则。`learning.py` 覆盖为：**只要 Worker 实际调用并返回，就必须审查**；学习入口不能通过关闭通用 runtime flag 发布未经审查的生成草稿。Gate 未放行仍先扣留，未调用 Worker 的标准止答/拒绝说明不追加审查请求。

复用原 `_review_output_answer`、`decide_reviewed_release`、引用审计和本轮上下文哈希。普通概念题提交 direct_answer/reasoning 两项，显式比较维度继续沿已有有界清单。Reviewer 须返回逐项草稿摘录，程序校验齐全、真实、不同摘录、本轮哈希，以及证据 ID、内容哈希和源文摘录；缺项、旧回执、伪引用、审查不可用均扣稿。

在审查调用前，活动状态明确切到 `output_review`，提示草稿尚未发布；原阶段耗时输出可看到“答案复核”。比较计划仍在审查前和发布前检查语料版本；**普通概念题没有新增整轮语料文件版本锁**，不可据此宣称所有来源变更均已覆盖。

当前另起一轮审查调用，但仍使用同一千问客户端/模型配置，没有新增异构模型投票。单独上下文能分工，不能保证两次判断的错误独立。

## 正常、失败与代价

| 案例 | 实测行为 |
| --- | --- |
| 明确概念答案与完整回执 | `guided/answered/released_model_reviewed`，审查时尚无新会话快照，结束后会话与最终答复一致 |
| 原三道空泛脚本题，Reviewer 自报 supported | `review_withheld/answer_coverage_contract_failed`，原草稿不进入最终答复或近期会话 |
| issue/uncertain、坏 JSON/对象、缺覆盖项、伪/重复摘录、旧回执、伪 ID/来源摘录、空 claims | 共 13 种模式均扣稿，错误原文不进入普通返回 |
| 交付后把检索片段哈希破坏 | 引用审计失败，扣稿 |
| 最终审查 403 / 503 一直失败 | 403 只试一次；503 最多两次，均扣稿 |
| 首次审查 503，第二次成功 | 总调用 5 次；修复重试事件携带异常原文的问题，仅记录受控错误类型/HTTP 状态 |
| 临时假预算只余 route/reviewer/worker 三次 | 第四次在发送前被拒，计数不超过 3，已生成草稿扣留 |
| 无资料、缺比较主体、高风险拒绝 | 均仅 route/reviewer 两次，无 Worker 或最终审查 |

普通生成答案正常从 **3→4 次**角色调用，严格生成答案仍为 **4 次**；现在 guided/deep 主要区分证据强度和覆盖要求，不能再把 guided 叫作少一次模型请求的快速路径。真实延迟/token/货币成本尚未测，不能宣称提速。

三组 Skill 脚本实验从 **16→20 次**调用：route 6、reviewer 6、worker 4、output_reviewer 4。原坏脚本产生的四份草稿都扣留；实验仍生成六份最终答复/证据的待评分包，人工标签 0/6、usage 与货币成本保持未测。新报告在本机 `artifacts/experiments/skill_da02a0e78e47/`。

## 不能把契约当作语义证明

另有一个刻意注入的“盲目 Reviewer”案例：草稿错误地说不同键永远不会落到同一槽位、完全不需要处理冲突；Reviewer 仍给 supported，回传真实证据摘录、当前哈希和完整草稿覆盖。**程序仍会放行这个语义错误答案。** 该测试保留，用来说明当前边界。

本轮解决的是发布前有实际审查、程序契约失败时扣稿及状态/成本可观察；没有证明所有结论都被原文蕴含，也没有消除幻觉。真实正确性、误拦以及同模型相关错误仍需 S2 独立复核；不把错误模型的自报支持率当正确率。
